# Tadpole OS Data Retention Policy & GDPR Guidelines

This document details how Tadpole OS complies with standard GDPR deletion guidelines and manages the lifecycle of data generated by autonomous agent swarms.

## Data Inventory

Tadpole OS stores the following categories of data within the persistent SQLite layer (`data/tadpole.db`):
1. **Agent Metadata**: Identity, name, department, active models, configurations.
2. **Quota Records**: Budget allocations and current expenditures.
3. **Sync Manifests**: Watch folders and URIs configured for scheduled agent RAG data ingestion.
4. **Fallback Memories**: Simple SQLite memory records.
5. **Agent Hires**: Logs of inter-agent tasks and collaborative hire budgets.
6. **Audit Trails**: SHA-256 chained transaction logs tracking security decisions.

## GDPR Right to Erasure (Cascading Deletion)

When an operator requests the deletion of a specific agent (via `DELETE /v1/agents/:id`), Tadpole OS carries out a **Cascading Deletion Transaction** to prevent data fragmentation and eliminate residual PII:

- **Agent Identity**: Purged from `agents` table.
- **Budget quotas**: Purged from `agent_quotas` table.
- **Data ingestion hooks**: Purged from `sync_manifest` table.
- **Memories**: Purged from `fallback_memories` table.
- **Collaborations**: Purged from `agent_hires` table (both as requester and worker).
- **Audit Records**: Purged from `audit_trail` table.

## Retention Schedules

- **Audit Trails**: Retained for 90 days. Can be cleared earlier by executing a manual purge command.
- **Continuous Logs**: Stored under `.tmp/` and pruned automatically when size exceeds 500MB.
